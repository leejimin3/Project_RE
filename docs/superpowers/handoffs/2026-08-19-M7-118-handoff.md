## 5. 이번 세션에서 알아낸 것 (함정)

### ★ Cascade 팩 머티리얼을 Niagara 에 쓰면 조용히 회색 사각형이 된다

**이번 세션 최대 함정이다.** 팩 머티리얼은 `bUsedWithParticleSprites` 만 켜져 있고
`bUsedWithNiagaraSprites` 는 꺼져 있다(실측 7종 전부 False). 이 플래그가 없으면 Niagara
스프라이트 렌더러가 **엔진 기본 머티리얼로 폴백한다** — 화면에 텍스처 없는 불투명 회색
쿼드가 뜨고, **로그도 에러도 안 남는다.**

ISM 쪽 `bUsedWithInstancedStaticMeshes` 와 같은 계열이다. `GetMaterial()` 은 정상값을
돌려주므로 코드로는 절대 안 잡힌다.

→ `scripts/fix_vfx_pack_usage.py`. 대상을 하드코딩하지 않고 **변환물의 실제 의존성에서 뽑는다.**

한참 헤맸던 이유는 진단 순서를 잘못 잡아서다. 처음엔 스케일을 의심해 0.25 → 0.03 으로
줄였는데 사각형이 **크기만 작아진 채 그대로** 남았다 — 그 시점에 이미 "스케일 아님" 이
확정됐는데도 변환 실패 쪽을 더 팠다. 의존성을 찍어 보니 머티리얼은 멀쩡히 붙어 있었다.

### `-ExecCmds` 에 공백이 있으면 CVar 가 조용히 무시된다

PowerShell `Start-Process -ArgumentList` 가 공백에서 인자를 쪼갠다.

```powershell
# 안 먹는다 — 쪼개져서 CVar 가 전달되지 않는다
$args = @('...', '-ExecCmds=re.Cheat.PlayerInvincible 1, re.Debug.ScreenshotFrame 600')

# 먹는다 — 통짜 문자열 + 내부 따옴표, 쉼표 뒤 공백 없음
$a = '"<uproject>" Main -game ... -ExecCmds="re.Cheat.PlayerInvincible 1,re.Debug.ScreenshotFrame 600"'
Start-Process $UE -ArgumentList $a
```

무적이 안 걸린 줄 모르고 돌렸다가 플레이어가 죽어 SimProbe DEFEAT 로 조기 종료됐다.
**에러가 아니라 "그냥 안 걸린" 상태**라 로그를 봐야만 안다.

### 헤드리스 프로브는 `-unattended` 게이트다 — 빼면 자동종료가 사라진다

`REPlayerController.cpp:154` — `if (HasAuthority() && FApp::IsUnattended())` 안에서만
프로브가 돈다. 프로브가 끝나면 `REGameMode::NotifyProbeComplete()` 가
`FPlatformMisc::RequestExit` 를 부른다(~610틱).

→ **임의 프레임 스크린샷을 찍으려면 `-unattended` 를 빼라.** 그러면 게임이 계속 돌아
`re.Debug.ScreenshotFrame` 에 큰 N 을 줄 수 있다. 대신 프로세스를 직접 죽여야 한다.

### 보스 페이즈는 런마다 다르다 — 곡사탄 화면을 노리려면 사후 대조

`REGameMode.cpp:264` 가 `StartFiring(FMath::Rand())` 로 시드를 준다. 즉 **결정적이지 않다.**
곡사탄 마커/폭발을 찍으려면 N 을 몇 개 바꿔 돌린 뒤, 로그의
`Boss FireArtillery: Shape=..` 시각과 `DebugScreenshot: 요청` 시각을 대조해 **비행시간 1.5s
안에 들어온 런을 고른다.** (Artillery 페이즈 4s / 일제사 간격 1.8s / 비행 1.5s)

### 곡사탄 착지점은 바닥보다 아래다

`GroundZ = BossLoc.Z + MarkerGroundOffset` = 90 − 88 = **Z 2**. Main 레벨 바닥 윗면은 **Z 40**.
그대로 이펙트를 놓으면 바닥에 묻힌다. 마커가 `MarkerZOffset 55`, 폭발이 `ExplosionZOffset 55`
인 이유가 전부 이것이다. **곡사탄 위치에 뭘 놓든 이 38uu 를 먼저 생각해라.**

### Niagara 는 파이썬으로 못 고친다 — Cascade 원본은 고칠 수 있다

`UNiagaraSystem::EmitterHandles` 도 `UParticleSystem::Emitters` 도 **protected** 라 파이썬에서
못 읽는다. 그래서 변환이 끝난 Niagara 시스템은 이미터를 뺄 수도, 수명을 바꿀 수도 없다.

우회 두 가지를 썼다:

- **이미터 제외** — 변환기 모듈이 들고 있는 `ueFxUtils` 참조를 가로채 목록에서 뺀다.
  엔진 변환 로직을 복사하지 않으므로 엔진이 바뀌어도 같이 굴러간다
- **수명 단축** — `FXConverterUtilitiesLibrary.get_lod_level_modules()` 로 Cascade 원본
  모듈에는 접근이 된다. 거기서 lifetime 분포를 **인메모리로만** 깎고 변환한다.
  팩 애셋은 저장하지 않는다(mtime 불변으로 확인)

### 변환기 플러그인은 BuildId 가 안 맞아 처음엔 로드에 실패한다

```
Plugin 'CascadeToNiagaraConverter' failed to load because module ... could not be found.
```

스톡 플러그인 DLL 이 이 소스빌드와 BuildId 가 다르다. **프로젝트 빌드를 한 번 돌리면**
매니페스트가 갱신돼 로드된다(DLL 재컴파일은 없었다).

### `delete_asset` 은 인메모리다 — 파일이 남아 경로를 점유한다

`rename_asset` 으로 그 경로에 다른 애셋을 옮기려 하면 실패한다. 변환은 성공했는데 이동만
두 번 실패했다. **`rm -f` 로 파일을 직접 지우는 쪽이 확실하다** (`M_ArenaSky` 재생성도 같은 방식).

### `-ExecutePythonScript` 인자는 마지막 토큰에 따옴표가 붙어 온다

`--force"` 가 되어 `"--force" in CMD.split()` 이 False 가 된다. 앞 세션 문서에 있던 함정인데
새 스크립트에서 그대로 다시 밟았다. **모든 인자 파서에 `.strip("\"'")` 을 넣어라.**

### Git / PR

Gitflow. `dev` 에서 `feature/M7-...` 분기 → PR base `dev`.
이슈/PR 메타 6개 필드 전부 채운다(`--label --milestone --assignee --project`, Reviewer 생략).

**`Closes #N` 은 dev 머지로는 발동하지 않는다**(기본 브랜치 전용). 머지 후 이슈를
수동으로 닫아라 — 이 프로젝트 관례다.

### 옛 세션에서 여전히 유효한 항목

- **`Config/DefaultGame.ini` 가 C++ 기본값을 덮는다.** `BulletSpeed=200`(헤더 300),
  `BulletLifetime=15.0`(헤더 3) → 실사거리 3000uu. 사거리를 따질 일이 있으면 **ini 를 먼저 봐라**
- **`BlockAll` 이 우클릭 이동을 막는다.** 우클릭 이동은
  `GetHitResultUnderCursor(ECC_Visibility)` 다(`REPlayerController.cpp:283/308/371`).
  구조물에는 엔진 기본 프로파일 **`InvisibleWall`** 을 써라 — 전부 막되 `ECC_Visibility` 만 통과
- **몽타주는 슬롯이 없어도 재생된다.** `MM_Pistol_Fire_Montage` 는 `Arms` 슬롯인데
  `ABP_Unarmed` 에는 `DefaultSlot` 뿐이라 **사격 애님이 화면에 나온 적이 없다.**
  `Montage_Play` 반환값도 `Montage_IsPlaying` 도 정상값을 준다 — 로그로는 절대 안 잡힌다.
  `#120` 에 상체 슬롯 분리 작업으로 들어가 있다
- **애님 재생 판정은 본 좌표로.** `Mesh->GetSocketTransform(TEXT("thigh_l"), RTS_Component)`
  가 프레임마다 변하면 재생 중. **`-nullrhi` 에서는 본이 갱신되지 않는다** — 실 RHI 필수
- **Fab 애셋 임포트가 `.uproject` 에 플러그인을 추가해 에디터가 안 열릴 수 있다.**
  임포트할 때마다 `git diff Project_RE.uproject` 로 확인해라
  (Ithris·VFX 팩 임포트에서는 오염 없었다)
