## 3. ★ 다음 작업 — #121 디자인 (사람 몫)

**PR #135 가 열려 있다.** 배관은 끝났고 남은 것은 디자이너 작업이다.

### 왜 내가 못 만드나

**위젯 트리는 파이썬으로 못 채운다.** `UWidgetBlueprint` 의 `widget_tree` 프로퍼티가 노출돼
있지 않고 트리를 짜 줄 에디터 라이브러리도 없다(실측). `WidgetBlueprintFactory` +
`parent_class` 로 **껍데기 생성까지만** 된다.

### 현재 상태

- `Content/UI/WBP_PlayerHud` (부모 `UREPlayerHudWidget`), `Content/UI/WBP_Result`
  (부모 `UREResultWidget`) — 둘 다 **트리가 비어 있다**
- 컨트롤러가 WBP 클래스를 먼저 찾고, 없으면 C++ 클래스로 폴백한다(`ResolveWidgetClass`)
- **C++ 트리 구성이 폴백으로 남아 있다.** 지금 HUD 는 예전 모습 그대로 뜬다 — 화면이 비는
  구간이 없다. 기존 `Initialize()` 의 재진입 가드가 그대로 폴백 스위치가 됐다:
  `if (!WidgetTree || HealthBar) return true;` / `if (WidgetTree && !ResultText) { ...구성... }`

### 할 일

`Content/UI/WBP_PlayerHud` / `WBP_Result` 를 열어 아래 이름으로 위젯을 배치하고 스타일을 입힌다.

**WBP_PlayerHud**

| 이름 | 타입 | 쓰임 |
|---|---|---|
| `HealthBar` | ProgressBar | HP 비율 |
| `HealthText` | TextBlock | `HP 100/100` |
| `DashBar` | ProgressBar | 대쉬 쿨다운 비율 |
| `DashText` | TextBlock | `DASH` / 남은 초 |
| `BulletText` | TextBlock | 화면상 투사체 수 |
| `BulletBox` | VerticalBox | 투사체 묶음 — `re.Debug.HudBulletCount 0` 이 통째로 숨긴다 |

**WBP_Result** — `ResultText` (TextBlock)

### ★ 전부 아니면 전무다

`UUserWidget` 의 루트는 하나뿐이라 바인딩된 위젯과 C++ 가 만든 루트를 섞으면 루트가 둘이 된다.
**하나라도 만들면 C++ 폴백이 통째로 꺼진다** — 위 목록을 다 갖춰야 한다.

이름을 틀리면 **조용히** 바인딩이 끊기고 그 값만 안 갱신된다. `BindWidgetOptional` 이라
컴파일은 통과한다 — 화면으로만 잡힌다.

### 완료 게이트

- HUD 가 엔진 기본값처럼 보이지 않는다 (스크린샷)
- **표시값 정확성 불변.** 검증법: `re.Debug.ScreenshotUI 1` 로 찍고, 화면의 `PROJECTILES N` 이
  같은 프레임 로그의 `DebugScreenshot: 요청 (... live=N ...)` 와 일치하는지 대조한다
  (이번에 32/32 로 확인했다). HP·대쉬는 육안
- `re.Debug.HudBulletCount 0` 에서 PROJECTILES 줄만 사라지고 HP/DASH 유지
- 디자인이 끝나면 C++ 폴백 코드를 걷어낼지 따로 판단

## 5. ★ 이번 세션에서 알아낸 것 (함정)

### 애디티브 애님은 애디티브 슬롯 없이는 화면에 안 나온다

**이번 세션 최대 함정이다.** `MM_Pistol_Fire` 는 `AAT_ROTATION_OFFSET_MESH_SPACE` 애디티브다.
일반 슬롯으로 재생하면 델타만 남아 **화면상 아무 변화가 없다.**

그런데 성공 신호는 전부 정상으로 나온다:

- `Montage_Play` 가 정상 길이를 돌려준다 (`[Attack] fire montage len=0.67`)
- `Montage_IsPlaying` 이 true
- **데디 검증의 "발사 몽타주 재생" 항목도 PASS 로 찍힌다**

전부 슬롯/애디티브 여부와 무관한 값이다. **화면으로만 잡힌다.** 애님이 안 보이면
`additive_anim_type` 을 먼저 찍어라.

→ 해결은 비-애디티브 애님(`MM_Pistol_DryFire`)으로 교체. 애님BP 를 안 건드린다.

### 파이썬 쓰기가 조용히 무시되는 프로퍼티가 있다

`UAnimMontage.slot_anim_tracks` 는 `set_editor_property` 가 **예외도 없이 no-op** 이다.
되읽으면 옛 값이다. 저장 전에도 이미 안 바뀌어 있다(인메모리 단계에서 이미 무시).

`fix_*` 류 스크립트에는 **저장 후 재읽기 검증**을 반드시 넣어라. 이번에 그 검증이 잡았다.

### UE 5.8 파이썬에서 막힌 프로퍼티들 (실측)

| 대상 | 상태 | 우회 |
|---|---|---|
| `SkeletalMesh.imported_bounds` | 미노출 | `mesh.get_bounds()` |
| `Skeleton.sockets` / `StaticMesh.sockets` | protected | 액터 스폰 후 `comp.get_all_socket_names()` |
| `AnimMontage.slot_anim_tracks` 쓰기 | 조용히 무시 | 없음 — 애셋 편집은 에디터에서 |
| `WidgetBlueprint.widget_tree` | 미노출 | 없음 — 트리는 디자이너에서 |
| `NiagaraSystem.EmitterHandles` | protected (#119) | 변환기 후킹 / Cascade 원본 수정 |

**파이썬으로 애셋을 고치려 들기 전에 되는지부터 찍어봐라.** 안 되는 쪽이 꽤 많다.

### 엔진에 빔 Niagara "시스템"이 없다

모듈(`Niagara/Content/Modules/Beams/`)과 이미터 템플릿(`StaticBeam`/`DynamicBeam`)뿐이라
이 리포의 "복제해서 쓰기" 관례를 적용할 대상이 없다. 시스템 조립은 위 표대로 막혀 있다.

→ 빔은 **실린더 메시 + 자체 저작 머티리얼**로 냈다. 머티리얼 저작은 이 리포에 이미 굴러가는
경로다(`make_bullet_material.py`). 팩 의존이 없어 버전관리되는 부수 이점도 있다.

### 밝은 바닥 위에서 Additive 는 흰색으로 포화된다

빔 룩을 두 번 되돌렸다. (1) Additive 는 아레나 바닥이 밝은 라벤더라 노란 빔이 **흰 실선**이
됐다 → Translucent. (2) `Strength` 6 은 Translucent 에서도 톤매퍼를 넘겨 다시 흰색 →
**1 근처여야 색이 남는다.** (3) `disable_depth_test` 를 켰더니 빔이 캐릭터 몸통 위에 덧그려져
플레이어를 가렸다 → 껐다.

### 화면 1픽셀 ≈ 1.9uu — 얇은 지오메트리는 실측으로 안 보인다

카메라 1500uu · FOV 90 · 1600px 기준이다. 처음 잡은 빔 굵기 3uu 는 **1.6픽셀**이라
"빔이 안 나온다"고 오진할 뻔했다. 20uu ≈ 10픽셀.

**기하가 틀린 건지 룩이 약한 건지 가르려면 로그를 찍어라.** `[Attack] beam start/end/len` 을
넣고 나서야 기하가 정확함이 확정됐다(그 로그는 남겼다).

### `re.Debug.ScreenshotFrame` 은 엔진 틱이 아니라 렌더 프로세서 실행 횟수다

탄이 없는 프레임에는 프로세서가 조기 반환해 카운터가 안 오른다. 그래서 **런마다 엔진 틱과의
오프셋이 다르고**, 큰 N(130+)은 프로브가 끝날 때까지 도달 못 하는 런도 있다.

0.06초짜리 이펙트를 이 방식으로 잡으려다 **6런 연속 1프레임씩 빗나갔다.** 그래서
`re.Debug.FireFxSec` 을 만들었다 — 검증 때 노출을 3초로 늘리면 아무 프레임에서나 찍힌다.
**짧은 코스메틱을 검증할 일이 또 생기면 셔터를 맞추지 말고 노출을 늘려라.**

### 보스 페이즈는 런마다 다르다 — 사후 대조가 유일한 방법

`StartFiring(FMath::Rand())` 라 결정적이지 않다. 페이즈별 스크린샷을 찍으려면 N 을 바꿔
여러 번 돌린 뒤 로그의 `Boss Phase:` 시각과 `DebugScreenshot: 요청` 시각을 대조해 고른다.
Fan 진입 직후 0.5초는 아직 이전 색이다(첫 발사가 그때라 외관이 안 바뀐 상태).

### 메시가 캡슐보다 커도 판정은 안 깨진다

`CharacterMesh` 콜리전 프로파일이 `Pawn` 채널을 무시하므로 자동사격 트레이스(`ECC_Pawn`)는
**캡슐에만** 맞는다. 골렘을 캡슐 1.9배로 두고도 `hit boss` 가 그대로 났다.
대가는 시각/충돌 불일치(플레이어가 골렘 발목 안으로 파고듦)뿐이다.

### 에디터가 열려 있으면 빌드가 통째로 거부된다

```
Unable to build while Live Coding is active. Exit the editor and game, or press Ctrl+Alt+F11
```

이번에 한 번 물렸다. `Get-Process | Where ProcessName -like "*Unreal*"` 로 확인하고,
**커맨드라인이 `Main -game ...` 이 아니면 사람이 연 에디터다 — 죽이지 말고 물어봐라.**

### 코드와 검증기를 같은 커밋에서 함께 바꾸지 마라

`dedi-verify.ps1` 이 `[Attack] fire montage len=` 문자열로 클라 재생/서버 생략을 판정한다.
재생 방식을 몽타주 → 다이나믹 몽타주로 바꾸면서 로그 문구를 바꾸고 싶었지만 **그대로 뒀다** —
바꿨으면 기존 어서션이 새 경로를 검증하지 못했다. (다이나믹 몽타주도 실제로 `UAnimMontage` 라
문구가 틀린 것도 아니다.)

`Target is up to date` 로 0 액션이 뜨면 **아무것도 검증되지 않은 것이다.** 유니티 섀도잉

```bash
cd E:/UnrealProjects/Project_RE && MSYS_NO_PATHCONV=1 \
  "$UE/UnrealEditor.exe" "E:/UnrealProjects/Project_RE/Project_RE.uproject" Main \
  -game -nullrhi -unattended -nosplash -NoSound -log=RE_probe.log
```

기대 출력(전부 나와야 한다):
```
[Attack] fire montage len=0.80          ← DryFire 길이. 애님 교체가 먹었다는 증거
```

프로브는 `-unattended` 게이트다(`REPlayerController.cpp` 의 `FApp::IsUnattended()`).
빼면 자동종료가 사라지므로 임의 프레임 스크린샷을 찍을 때는 빼되 프로세스를 직접 죽여야 한다.

### 데디 검증

RPC 시그니처·서버 로직·`Config/*.ini` 를 건드렸으면 **재빌드 + 재쿡이 필수**다.

```powershell
Build.bat Project_REServer Win64 Development -Project=... -DisableAdaptiveUnity -WaitMutex   # ~90초
RunUAT.bat BuildCookRun -project=... -noP4 -platform=Win64 -server -noclient `
  -serverconfig=Development -cook -stage -pak -skipbuild -utf8output                          # ~2분
scripts\dedi-verify.ps1 -Clients 2                                                            # 21항목
```

`-skipbuild` 를 빼먹지 마라. 클라 전용 변경(렌더·FX·UI·머티리얼)은 재스테이징 불필요 —
`-SkipStaleCheck` 로 넘긴다. **습관적으로 붙이지 마라**(#103: 낡은 exe 로 16항목 PASS 를 받은 적 있다).

빔처럼 클라에서만 도는 것을 검증하려면 **런 디렉터리의 client/server 로그를 직접 대조해라.**
이번에 `[Attack] beam` 이 client1 3건 / client2 3건 / server 0건으로 나와 원격 재생과
데디 가드를 동시에 증명했다.

### 시각 검증

```powershell
$UE='E:\UnrealEngine-5.8\UnrealEngine-5.8\Engine\Binaries\Win64\UnrealEditor.exe'
$a='"<uproject>" Main -game -windowed -ResX=1600 -ResY=900 -nosplash -NoSound ' +
   '-log=RE_shot.log -ExecCmds="re.Cheat.PlayerInvincible 1,re.Debug.ScreenshotFrame 1200"'
$p = Start-Process $UE -ArgumentList $a -PassThru
if (-not $p.WaitForExit(150000)) { $p.Kill() }
```

산출물 `Saved/Screenshots/WindowsEditor/`. **파일이 새로 생겼는지 반드시 확인해라** —
`ls -t` 만 믿으면 직전 런의 이미지를 집어 "안 변했다"고 오진한다.

- `-ExecCmds` 는 **통짜 문자열 + 쉼표 뒤 공백 없음**이라야 한다. PowerShell 이 공백에서
  인자를 쪼개면 CVar 가 조용히 무시된다(에러가 아니라 "그냥 안 걸린" 상태)
- HUD 를 찍으려면 `re.Debug.ScreenshotUI 1`
- 자동 발사 경로는 **`-unattended` 프로브뿐**이다(마우스 입력 구동이라 일반 런은 안 쏜다).
  발사 순간을 찍으려면 `-unattended` + `re.Debug.FireFxSec` 로 노출을 늘려라
- 캐릭터를 가까이 보려면 `-ExecCmds` 에 `FOV 25` 를 넣는다
- 탄막을 채우려면 `re.Profiling.KeepFiring 1`, 50k 는 `re.Bullets.Count 50000`

### 프로파일

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/profile.ps1 -Bullets 50000 -Label "태그"
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/profile-stats.ps1 -Run "Saved\Profiling\<런디렉터리>"
```

기준선 `docs/profiling/M6-gpu-breakdown.md` 부록 A: **50,000발 Frame p99 15.00 ms**, 게이트 **16.6 ms**.

- 하네스는 `re.Fx.Explosions 0` 으로 폭발을 뺀다(#98)
- **인스턴스 수를 반드시 확인해라.** 0발로 조용히 측정되는 함정이 있다(#46)
- 표본 하나로 단정하지 마라

  지연·외관 알림을 타지 않는다. 프로파일 시작 창이 오염되지 않는다

### 옛 세션에서 여전히 유효한 항목

- **`Config/DefaultGame.ini` 가 C++ 기본값을 덮는다.** `BulletSpeed=200`(헤더 300),
  `BulletLifetime=15.0`(헤더 3) → 실사거리 3000uu. 사거리를 따질 일이 있으면 **ini 를 먼저 봐라**
- **`BlockAll` 이 우클릭 이동을 막는다.** 구조물에는 엔진 기본 프로파일 **`InvisibleWall`** 을
  써라 — 전부 막되 `ECC_Visibility` 만 통과
- **애님 재생 판정은 본 좌표로.** `-nullrhi` 에서는 본이 갱신되지 않는다 — 실 RHI 필수
- **Fab 애셋 임포트가 `.uproject` 에 플러그인을 추가해 에디터가 안 열릴 수 있다.**
  임포트할 때마다 `git diff Project_RE.uproject` 로 확인해라(Stone_Golem 은 오염 없었다)
- **곡사탄 착지점은 바닥보다 아래다.** `GroundZ = BossLoc.Z + MarkerGroundOffset` = **Z 2**,
  Main 레벨 바닥 윗면은 **Z 40**. 곡사탄 위치에 뭘 놓든 이 38uu 를 먼저 생각해라
- **Cascade 팩 머티리얼을 Niagara 에 쓰면 조용히 회색 사각형이 된다**(`bUsedWithNiagaraSprites`).
  `GetMaterial()` 은 정상값을 돌려주므로 코드로는 절대 안 잡힌다 — `fix_vfx_pack_usage.py`
- **`delete_asset` 은 인메모리다** — 파일이 남아 경로를 점유한다. `rm -f` 가 확실하다
- **`-ExecutePythonScript` 인자는 마지막 토큰에 따옴표가 붙어 온다.** 모든 인자 파서에
  `.strip("\"'")` 을 넣어라
- **모든 생성기는 `save_asset(FULL, False)` 를 쓴다.** 기본값(`only_if_is_dirty=True`)이면
  `MaterialEditingLibrary` 변경이 dirty 를 안 세워 저장이 조용히 건너뛰어진다
