## 5. 이번 세션에서 알아낸 것 (함정)

### ★ `EditorAssetLibrary.save_asset()` 이 조용히 아무것도 안 한다

**이번 세션 최대 함정이다.** 기본값이 `only_if_is_dirty=True` 인데 `MaterialEditingLibrary` 로
만든 변경은 패키지를 dirty 로 표시하지 않는다. 그래서:

```
"RE_SKY: 생성 완료" 로그는 찍히는데 uasset 타임스탬프는 그대로다
```

하늘 색을 아무리 바꿔도 화면이 안 변하던 진짜 이유. 재생성이 **여러 시간 분량** 조용히 버려졌다.
→ 생성기 전부 `save_asset(FULL, False)` 로 고쳤다. **새로 스크립트를 쓸 때도 반드시 False.**

### MaterialInstance 파라미터 오버라이드도 저장이 안 됐다

`set_material_instance_*_parameter_value` → `update_material_instance` → `save_asset(..., False)`
까지 해도 MI 에는 **직전 실행 값이 그대로** 남았다(이미 삭제된 파라미터 이름까지 남아 있었다).
원인 미규명.

→ 하늘은 MI 계층을 걷어내고 **머티리얼 기본값에 색을 직접 굽는다**(`make_arena_sky.py --hor_r=..`).
바닥은 MI 를 쓰되 값이 실제 반영됐는지 화면으로 확인할 것.

### 자동노출 EV 0 고정 → 이미시브 0.03 이 중간톤으로 뜬다

`PostProcessVolume` 이 자동노출을 EV100 = 0 으로 잠근다(`setup_level_lighting.py`).
그래서 밤하늘을 만들려면 이미시브가 **한 자릿수 더 낮아야** 한다(0.03 → 0.005 수준).
"계속 단색 보라"의 정체가 이것이었다.

### 머티리얼 그래프가 연결도 에러도 없이 0 을 뱉는다

`AbsoluteWorldPosition → Normalize → DotProduct → Noise` 로 은하수 띠를 만들었더니 출력이 0.
구를 눈앞에 놓고 찍으면 순수 검정, 항을 분리해도 검정. **원인 미규명.**

→ 그 체인을 버리고 화면으로 검증된 노드만 쓴다:
`VertexNormalWS` + `ComponentMask` + `TextureCoordinate` + `TextureSample` + `Multiply/Add/Lerp/Abs/OneMinus/Clamp/Subtract/Divide`.
**은하수 띠는 구 UV 의 V 가 곧 위도**라 내적 없이 만들 수 있다.

> `make_arena_sky.py --only=base|band|nebula|stars|bigstars` 로 한 항만 이미시브에 직결할 수 있다.
> 여러 항을 더해 놓으면 어느 항이 0 인지 화면으로 구분할 수 없다. **조용히 죽은 항을 찾는 유일한 수단.**

### `Config/DefaultGame.ini` 가 C++ 기본값을 덮는다

```
BulletSpeed=200.000000      (REStatsSettings.h 기본값은 300)
BulletLifetime=15.0         (헤더 기본값은 3)
```

**실사거리 = 200 × 15 = 3000uu.** 헤더만 보고 900uu 로 계산했다가 "탄이 구조물에 안 닿는다"고
잘못 단언했다. 사거리를 따질 일이 있으면 **ini 를 먼저 봐라.**

### `BlockAll` 이 우클릭 이동을 막는다

우클릭 이동은 `GetHitResultUnderCursor(**ECC_Visibility**)` 다
(`REPlayerController.cpp:283/308/371`). 구조물에 `BlockAll` 을 주면 그 채널까지 막혀 클릭이
바닥 대신 구조물에 걸린다.

→ 엔진 기본 프로파일 **`InvisibleWall`**: 전부 막되 `ECC_Visibility` 만 통과. 한 줄이고
버전 의존도 없다(UE 파이썬 바인딩에 `CollisionResponse.ECR_IGNORE` 도 `.IGNORE` 도 없었다).

### 마커가 바닥에 묻혔다

`MarkerZOffset = 10` 인데 **Main 레벨 바닥 윗면이 Z=40** 이다. 예전 마커는 높이 100uu 짜리
Cylinder 라 윗부분이 삐져나와 보였는데, 두께 없는 Plane 으로 바꾸자 그대로 묻혔다. → 55 로 올림.

### 디렉셔널 라이트 pitch 가 0 이었다

원래 회전이 `(pitch=0, yaw=-30, roll=-46)`. pitch 0 은 빛을 **수평으로** 쏜다는 뜻이라 법선이
위인 바닥에는 cos(90°)=0, 직접광이 하나도 안 들어간다. 캐릭터(수직면)만 밝고 바닥이
새까맣던 진짜 원인. 알베도도 노출도 아니었다. → pitch −48.

레벨에 **완전히 동일한 DirectionalLight 가 2개** 있던 것도 이때 발견해 하나 지웠다.

### 디렉셔널 라이트가 2개 이상이면 노란 경고가 화면에 찍힌다

```
Multiple directional lights are competing to be the single one used for forward shading,
translucent, water or volumetric fog. Please adjust their ForwardShadingPriority.
```

필라이트를 추가하면서 떴다. 포트폴리오 영상에 그대로 들어간다. → `forward_shading_priority`
키=10 / 필=0 명시.

### SkyLight 실시간 캡처도 화면에 경고를 그린다

```
A sky light with real-time capture ... requires ... a mesh with a material tagged as IsSky.
Otherwise it will be black
SKYDOME MESH ... DOES NOT COVER THAT PART OF THE SCREEN
```

→ 실시간 캡처를 끄고(`--skylight_capture=0`, 기본값) 머티리얼의 `IsSky` 도 껐다. 앰비언트는
`intensity` 로 맞춘다.

### 구 UV 는 극점에서 수렴한다

카메라가 아래를 보므로 **아래쪽 극이 화면 하단 중앙**에 와서 별이 방사형 소용돌이로 뭉친다.
→ 하늘 구를 `roll 90` 으로 눕혀 극을 좌우로 보낸다(`setup_level_props.py --sky_roll`).

### `/Engine/BasicShapes/Sphere` 에는 콜리전이 있다

원점에 큰 구를 놓으면 플레이어 캡슐이 밀려 씬 밖으로 튕긴다. "바닥이 사라지고 캐릭터만
허공에 뜬" 화면의 정체. → `NoCollision`.

### 프롭 개수 = 드로우콜 = GT 시간

프롭 94개가 드로우콜을 96 → 222 로 늘려 50,000발 p99 를 15.00 → 16.98 로 밀어냈다.
`setup_level_props.py --density` 로 조절한다(기본 0.5).

### 팩 타일러블 MI 는 파라미터가 안 먹을 수 있다

`MI_StoneSurface_01`(부모 `MM_Base_POM`)의 `HUE` 를 2.5 → 8.0 으로 올려도 화면이 거의 안 변했다.
→ 팩의 **텍스처만** 가져다 우리 머티리얼에서 곱한다. 디테일과 밝기 통제를 둘 다 가진다.

### 헤드리스 스크린샷 프레임 조준은 여전히 불안정하다

`re.Debug.ScreenshotFrame N` 의 N 과 게임 프레임 대응이 런마다 흔들린다. **파일이 새로
생겼는지 검증하고 N 을 바꿔가며 재시도**하는 루프로 감싸야 한다. 안 그러면 `ls -t` 가
직전 런의 이미지를 집어 "안 변했다"고 오진한다(실제로 그렇게 한 번 속았다).

### 옛 문서에서 유효한 항목 (2026-08-17 인계분)

- **로코모션 애님은 `Acceleration` 으로 게이팅된다.** CMC 의 `Acceleration` 멤버는 오직
  `AddMovementInput` 에서만 채워진다. 패스팔로잉 이동은 `RequestedAcceleration` 을 쓰고 멤버는
  0 으로 남긴다. `ABP_Unarmed` 상태 전이가 `GroundSpeed > 3 AND GetCurrentAcceleration() != 0`
  이라, 서버 권위 분기에서도 `AddMovementInput` 을 넣어야 애님이 돈다(#126/PR #127).
  **애님BP 를 갈아끼울 때마다 이 게이팅을 확인하라.**
- **몽타주는 슬롯이 없어도 재생된다.** `MM_Pistol_Fire_Montage` 는 `Arms` 슬롯인데
  `ABP_Unarmed` 에는 `DefaultSlot` 뿐이라 **사격 애님이 화면에 나온 적이 없다.**
  `Montage_Play` 반환값과 `Montage_IsPlaying` 은 슬롯 유무와 무관하게 정상값을 준다 — 로그로는
  절대 안 잡힌다. #120 에 상체 슬롯 분리 작업으로 들어가 있다.
- **애님 재생 판정은 본 좌표로.** `Mesh->GetSocketTransform(TEXT("thigh_l"), RTS_Component)`
  값이 프레임마다 변하면 재생 중, 고정이면 정지. **`-nullrhi` 에서는 본이 갱신되지 않는다** —
  반드시 실 RHI(`-windowed`).
- **gitignore 된 애셋의 수동 셋업은 리포에 안 남는다.** Sarah(`Content/Adventure_Pack/`)는
  Compatible Skeletons 등록(Persona → Retarget Manager, Details 패널에 없음)과 `M_Hair` 노말맵
  지정을 새 환경에서 손으로 해야 한다. 절차는 PR #125 본문에 있다.
- **Fab 애셋 임포트가 `.uproject` 에 플러그인을 추가해 에디터가 안 열릴 수 있다.**
  임포트할 때마다 `git diff Project_RE.uproject` 로 확인하라. 안 쓰는 플러그인이면 지우는 게 제일 빠르다.
  (이번 Ithris 임포트는 오염 없었다.)
